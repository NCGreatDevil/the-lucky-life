# 求神功能说明书

## 1. 功能概述

求神功能是游戏的核心玩法之一，允许用户通过消耗活力来祈求好运，可能获得运气值提升、属性加成以及与神明建立关系。该功能结合了概率机制、属性系统和社交元素，为用户提供持续的游戏体验。

## 2. 功能流程

### 2.1 基础操作
- 用户点击"祈求好运"按钮
- 消耗30点活力值
- 触发随机事件和奖励

### 2.2 结果展示
- 展示祈求动画（2-5秒）
- 显示运气值变化
- 显示属性加成（如有信仰）
- 显示遇到的神明（如有）
- 显示好感度提升（如遇到神明）

## 3. 属性系统

### 3.1 活力系统
- 活力值范围：0-100
- 每次祈求消耗：30点
- 活力不足30点时无法祈求

### 3.2 运气系统
- 运气值范围：0-100（隐藏属性）
- 运气等级：1-6级
- 等级对应标签：
  - 1级：倒霉
  - 2级：不顺
  - 3级：平常
  - 4级：顺遂
  - 5级：好运
  - 6级：爆棚

### 3.3 运气增长机制
根据当前运气值确定增长范围：
- 0-5：增长范围 5-26
- 6-25：增长范围 5-51
- 26-75：增长范围 5-11
- 76-85：增长范围 5-11
- 86-95：增长范围 1-5
- 96-100：增长范围 1-4

**特殊规则**：
- 运气值最高不超过100
- 运气值为100时，不再显示增加提示，改为"你的运气已经到达顶峰，必定事事顺利，好运连连"
- 确保每次运气至少增加1点（除非已满100）

## 4. 神明系统

### 4.1 神明类型
共有11种神明，每种对应不同的属性加成：
- 秦本源：energy（能量）
- 苏生阳：vitality（活力）
- 孟怀德：morality（道德）
- 文知睿：intelligence（智力）
- 岳磐石：constitution（体质）
- 柳清妍：charm（魅力）
- 石恒坚：willpower（意志）
- 云心宁：emotion（情绪）
- 陈睦缘：popularity（人缘）
- 金宝盈：money（金钱）
- 周吉时：luck（运气）

### 4.2 神明属性
- 属性加成范围：每种神明有固定的最小值和最大值
  - 秦本源：energy +10~30
  - 苏生阳：vitality +10~30
  - 孟怀德：morality +1~3
  - 文知睿：intelligence +1~3
  - 岳磐石：constitution +1~3
  - 柳清妍：charm +1~3
  - 石恒坚：willpower +1~3
  - 云心宁：emotion +1~3
  - 陈睦缘：popularity +1~3
  - 金宝盈：money +1~100
  - 周吉时：luck +1~5
- 好感度系统：线性增长，LV0(0)-LV1(100)-LV2(300)-LV3(600)-LV4(1000)-LV5(1500)
- 专属信物：每种神明有独特的象征物品

## 5. 概率机制

### 5.1 无信仰状态
- 40%概率遇到神明
- 遇到神明时：
  - 80%概率从前3名好感度最高的神明中选择
  - 20%概率随机选择其他神明
- 首次遇到神明时好感度翻倍

### 5.2 有信仰状态
- 80%概率遇到供奉的神明
- 15%概率遇到其他神明
- 5%概率什么神都没有遇到

## 6. 信仰机制

### 6.1 供奉条件
- 神明好感度达到LV1（100点）后可选择供奉
- 一个用户只能供奉一位神明

### 6.2 供奉效果
- 获得对应神明的属性加成
- 祈求时优先遇到供奉的神明

### 6.3 更换神明
- 条件：新神明好感度达到LV1（100点）
- 代价：
  - 随机减少当前供奉神明对应属性值的10%-40%
  - 对原神明的好感度降至99（LV0）
- 更换后立即供奉新神明

### 6.4 放弃供奉
- 条件：有供奉的神明
- 代价：
  - 扣除当前供奉神明对应属性值的25%
  - 对该神明的好感度降至99（LV0）
- 放弃后回到无信仰状态

## 7. 好感度系统

### 7.1 好感度增长
- 每次遇到神明随机增加1-50点好感度
- 首次遇到的神明好感度翻倍（2-100点）

### 7.2 等级划分
- LV0：0-99点
- LV1：100-299点
- LV2：300-599点
- LV3：600-999点
- LV4：1000-1499点
- LV5：1500+点

### 7.3 好感度重置
- 拒绝供奉：好感度清零
- 更换神明：原神明好感度降至99
- 放弃供奉：该神明好感度降至99

## 11. API接口设计

### 11.1 祈求接口（POST /api/prayer）
**请求**：
- 无需请求体
- 通过Cookie中的session_token进行身份验证

**响应**：
```json
{
  "success": true,
  "luckGain": 5,
  "oldLuckLevel": 3,
  "newLuckLevel": 3,
  "luckLevelUp": false,
  "isMaxLuck": false,
  "newLuckLabel": null,
  "attributeGain": 15,
  "attributeType": "energy",
  "encounteredDeity": {
    "id": "deity_energy",
    "name": "秦本源",
    "imageDescription": "...",
    "imageUrl": "...",
    "attributeType": "energy"
  },
  "favorabilityResult": {
    "deityId": "deity_energy",
    "deityName": "秦本源",
    "favorabilityGain": 25,
    "newFavorability": 125,
    "newLevel": 1,
    "oldLevel": 0,
    "levelUp": true,
    "isFirstEncounter": false
  },
  "newVitality": 30,
  "newLuck": 45
}
```

**错误响应**：
- 401：未登录或会话过期
- 400：活力不足
- 404：用户属性不存在
- 500：服务器错误

### 11.2 神明信息接口（GET /api/deity-info）
**请求**：
- 无需请求体
- 通过Cookie中的session_token进行身份验证

**响应**：
```json
{
  "success": true,
  "worshippingDeity": {
    "id": "deity_energy",
    "name": "秦本源",
    "attributeType": "energy",
    "imageDescription": "...",
    "imageUrl": "...",
    "powerDescription": "...",
    "token": "元气玉轮",
    "personality": ["沉稳", "浩瀚", "包容"],
    "favorability": 125,
    "level": 1
  },
  "deityRelations": [
    {
      "deityId": "deity_energy",
      "deityName": "秦本源",
      "attributeType": "energy",
      "favorability": 125,
      "level": 1,
      "isWorshipping": true
    }
  ]
}
```

### 11.3 神明操作接口（POST /api/deity-action）
**请求体**：
```json
{
  "deityId": "deity_energy",
  "action": "accept" // 或 "reject", "switch", "abandon"
}
```

**操作类型**：
- `accept`：接受供奉（需要好感度≥100）
- `reject`：拒绝供奉（清空该神明好感度）
- `switch`：更换神明（需要新神明好感度≥100）
- `abandon`：放弃供奉（回归无信仰状态）

**响应示例（更换神明）**：
```json
{
  "success": true,
  "message": "已更换供奉为秦本源",
  "attributeLoss": {
    "attributeType": "intelligence",
    "loss": 15
  },
  "newDeity": {
    "id": "deity_energy",
    "name": "秦本源",
    "attributeType": "energy"
  }
}
```

| attribute_max | INT | 属性加成最大值 |

| luck_max | INT | 运气加成最大值 |
| encounter_rate | INT | 遇到概率（百分比） |
| created_at | TEXT | 创建时间 |

### 12.2 user_deities表（用户-神明关系表）
| 字段名 | 类型 | 说明 |
|--------|------|------|

| user_id | TEXT | 关联的用户ID |
| deity_id | TEXT | 关联的神明ID |

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | TEXT | 记录唯一标识符 |

## 13. 前端组件设计

- **祈求按钮**：触发祈求操作，显示消耗和状态
- **测试按钮**：管理员专用，恢复满状态
- **属性条**：显示能量和活力进度

- **祈求动画弹窗**：展示祈求过程和结果

### 13.2 神明关系卡片
- **未供奉且等级≥1**：显示"更换"按钮
- **已供奉**：显示"放弃"按钮
- **等级<1**：无操作按钮

### 13.3 状态管理
- 使用Vue 3 Composition API
- 使用Pinia进行全局状态管理
- 实时更新用户属性和神明关系

## 14. 错误处理

### 14.1 前端错误处理
- 网络请求失败：显示"操作失败，请稍后重试"
- 会话过期：提示重新登录
- 参数错误：显示具体错误信息

### 14.2 后端错误处理
- 401：未登录或会话过期
- 400：参数错误或条件不满足
- 404：资源不存在
- 500：服务器内部错误

## 15. 安全机制

### 15.1 身份验证
- 使用session_token进行身份验证
- Token哈希存储在数据库中
- 会话有过期时间

### 15.2 数据验证
- 所有输入参数进行验证
- 数据库操作使用参数化查询
- 防止SQL注入攻击

### 15.3 权限控制
- 管理员功能仅限特定用户
- 用户只能操作自己的数据
- 敏感操作需要二次确认
